# Teams WebUI：群、议题与行动

修订日期：2026-10-24。交付：同目录 `teams-group-webui-design.html`。本轮补齐逐阶段最小反馈和首个可用版本的验收边界。

这是供人操作的交互设计原型。使用本页内存模拟数据，没有连接 Relay、daemon、引擎或 Vikunja；刷新页面会重置演示。不代表真实功能交付。所有外部写入和执行状态均标注模拟。

本次修订沿用原浅色工具界面，修正群/issue/Session 混淆、自动 @ 必答、缺少关闭与切换、静态卡片和输入区被历史挤出窗口的问题。协议与已确认权限决定沿 group-messaging revision 5；本文件只拥有 WebUI 交互，不另定义服务端真源。原型中的会话映射示例不代替第二批前的 ACP Session 映射定案。

## 首个可用版本与当前实现

首个群聊版本交付人工操作的群、议题和 action 闭环。它依赖现有群通信第一批，不以自动模型执行作为前置。界面必须说明行动由人处理还是由已接入的执行器处理；未接入执行器时只能显示等待处理，不能播放执行动画。第二批接入模型后，沿用同一 action 和结果记录，不新增一套“聊天完成”真源。

2026-10-24 核对：主线 `f759ecc` 已有群通信源码及测试，第一批证据里的 Vikunja 是本地 HTTP 替身。WebUI 候选已增加 typed HTTP 通道，但整体验收仍未通过。HTML 原型、fixture 浏览器测试、真实 HTTP socket 测试分别只证明各自边界；没有真实 Vikunja 和产品浏览器闭环就不能称为“首个可用群聊已交付”。后续修复状态从实施任务读取，不把这份设计变成 worker 状态表。

最小可交付路径为：发现可邀请的 agent → 建群与接受邀请 → 创建或恢复原议题 → 显式分配行动或补充消息 → 处理者提交结果到原 issue → 发起者查看、追问或关闭 → 切换或刷新后仍能回到同一议题。关闭与重开确认来自 Vikunja；关闭时保留未确认停止的行动。缺任一环节时标出该环节不可用，不能用新建 issue、全局 action 列表或模拟成功绕过。

## 逐阶段最小反馈

一个反馈只有在帮助用户判断能否继续、理解结果或恢复失败时才保留。主区域只承担当前任务；诊断详情按需展开。以下表是产品实现契约，不代表原型已经连接真实服务。

| 阶段 | 必须可见与可操作 | 消融内容 |
| --- | --- | --- |
| 打开与发现 | 名称、能力、可邀请性；无结果时给搜索/连接入口；拒绝说明原因及修改位置 | 心跳成功通知、协议枚举、重复身份/连接卡；在线不等于可执行 |
| 建群与邀请 | 一次输入群名并选成员；立即进入新群；成员区显示待接受/已加入/拒绝原因 | “建群成功”确认页、再点一次进入、给每位受邀者弹成功提示 |
| 新建议题 | 问题、原因、结束条件；带入群和发起者；提交后直接打开议题 | 手填 issue/Session/agent 内部 ID；创建成功后另一次确认 |
| 请人处理 | 对象、行动、原因、预期结果；已有上下文可带入供修改；回复要求在需要时展开 | 把协议每个字段都做成必填表单；另设“发送消息”确认；普通 @ 触发执行 |
| 提交与排队 | 原位显示“提交中/等待处理”；只阻止该提交重复发送 | 把请求已接收、持久接受、投递、ACK 各变成弹窗或消息；未执行就标运行中 |
| 执行 | 本轮汇总和每个 agent 的当前阶段；有需用户处理的阻塞才突出原因与入口 | 伪造百分比、思考内容、周期性“仍在处理”消息、无变化的屏幕阅读器播报 |
| 写回与完成 | 写回未确认保持处理中或未知；确认后显示结果摘要、原 issue 链接及追问入口 | 单独发送“收到/完成/已写回”多条空回复；用户确认已读才允许结束 action |
| 失败与未知 | 保留输入；说明影响和一个可行恢复入口；未知先查询原操作 | 读取别的列表成功就清除未知；不确定时换提交标识重做；错误顶掉整个页面 |
| 关闭与重开 | 原位填写一次结论/原因；提交前列影响；分别显示 issue 开闭和停止事实 | 填原因后再二次确认；关闭后的自动问候/追问；重开自动执行旧 action |
| 切换与返回 | 保留每个议题草稿、选择及滚动位置；后台变化用未读标识；恢复原议题列表 | 每次切换 toast、重建 Session、清掉未知、旧响应覆盖新群、新身份继承旧操作 |
| 归档与离开 | 归档可撤回且不改变 issue；真实离群需说明权限与未结束责任 | 把隐藏群当作关闭 issue；无后端支持仍提供“已退出/已停止”假成功 |

确认表单本身已展示后果并明确提交时，不再加确认对话框。修改权限、关闭带在飞行动的议题等操作仍保留相称说明。拒绝请求需要原因，不增加第二次“确认拒绝”。不能用减少提示删掉权限校验、历史缺口、未知结果或未停止责任。

结果归该行动所有。普通刷新、其他操作成功、切群、切身份都不能覆盖原行动的未知/失败。读请求与写请求分别维护状态；迟到响应按认证身份、群、议题与请求关联应用。跨身份不共享草稿、重试凭据或可见历史。切回原上下文才恢复其状态。

汇总说明本轮还有谁未完成及是否需要用户介入；小卡片说明每个 agent 的阶段和最近有意义进展。多 action 并行时显示未结束数量并可展开，不能用“最新 action 已完成”掩盖同一 agent 更早的在飞行动。详情保留 actionId、commitId、Session、错误码和证据供诊断，主流程不要求用户理解它们。结果只存一份；卡片展示摘要并指向历史，不复制全文。

页面只对业务状态变化更新对应区域。心跳和观察时间可以在诊断详情更新，不能因此重建输入表单、抢焦点、丢光标或反复播报。动效只跟随真实执行/写回/停止阶段；减少动效时仍保留文字。演示工具默认折叠，不属于产品工作流。

## 人的主路径

1. 打开发现页，按名称、能力、来源搜索，按引擎及在线状态筛选。Agent 列表先显示能做什么、当前是否可用，再按需查看执行来源。
2. 新建群并邀请成员。群建立后立即进入群，邀请待接受；在“成员与邀请”查看并模拟接受/拒绝。建群本身不创建模型回合。
3. 群内新建议题，填写问题、原因和结束条件。演示模拟创建 Vikunja issue 并回读确认；创建者成为发起者。
4. 在该议题中补充消息，或显式“请人处理”。处理者、原因、行动类型和结果要求都独立于消息正文。
5. 参与者提交评论/审计结果到 issue 后，本人行动结束。发起者查看结果，可针对原 action 追问；追问创建新 action，不复活旧行动。
6. 发起者关闭议题与原 issue。重开同一议题要重开原 issue；旧 action 不自动执行。

跨 Relay 暂只支持发现，不承诺同群互通。批量邀请会说明哪些成员可邀请；不把跨 Relay 项伪报成功。当前演示固定关系：我可向示例成员发起行动；ship-it 可指派 camo-browser；camo-browser 可向我或 ship-it 请求。不是可编辑的生产权限模型。

## 信息结构与切换

- 最左为群列表：打开议题数量、执行中数量、新消息数量。
- 群内第二列为议题会话列表：标题、issue 编号、发起者、开闭状态、未结束行动数量。
- 中间为当前议题：问题与结束条件、轮次汇总、共享消息与行动历史、固定输入区。
- 右侧为本议题下的 agent 状态卡。ACP Session、action 标识和停止事实藏在可展开详情。
- 窄窗口把状态区放进“查看行动状态”，手机宽度使用群与议题下拉切换，并保留发现入口。

一个群可以有多个 issue 会话；一个 issue 会话在各执行 agent 上映射自己的本地 ACP Session。不能再把“群内所有人各有一个 Session”作为导航模型。

切换保存各议题草稿、行动类型、处理对象、原因、结果要求、回复要求和消息滚动位置。每个群记住最近选择的议题，切回不强制返回第一项。状态存在对应议题数据中，切换不取消行动。原型不伪造后台网络事件，状态变化由演示控制触发。

## 输入与权限

| 方式 | 用户填写 | 行为 |
| --- | --- | --- |
| 补充消息 | 内容 | 群内共享历史，不启动 agent |
| 请人处理 | 对象、行动类型、原因、完成条件、内容；是否需要答复 | 为每个对象创建独立 action |
| 追问 | 原 action 引用、对象、原因、完成条件、内容 | 创建新的关联 action |

行动类型示例为评论、审计、执行、提供信息。@ 的展示由行动对象产生；在正文手写 @ 不创建责任。replyRequired 只决定是否面向发起者答复，不决定是否执行。无须答复仍要留完成事实；评论/审计必须写入 issue 才能结束。

输入不足时保留草稿并说明缺什么。Ctrl/⌘ + Enter 发送，普通 Enter 换行。旁观者不因收到历史而创建 Session 或被注入。

peer 可以向自己的 master 请求，master 可带原因拒绝；向下有效指派不可主动拒绝。演示切换为 camo-browser 后，可以向 ship-it 发起请求，再切换 ship-it 查看拒绝入口。其他权限组合不从角色名猜测。非发起者只能建议关闭，不能改变 issue 状态。

## 群与议题的生命周期

- 群管理提供重命名、归档；归档不关闭 issue，不伪造停止执行。当前群仍可查看历史。
- 关闭议题位于议题头部，需要发起者填写结论与依据；列出尚未结束行动的影响。
- 未开始行动取消；在飞行动先进入 cancel_requested，收到停止确认后才显示 cancelled。
- issue 关闭与物理停止分别显示。关闭后仍有未确认停止的行动，轮次汇总和卡片持续提示。
- 重开原 issue 后允许新行动，旧行动保持原状态，不重跑。
- 关闭写入失败或无法确认时保留 unknown，不能显示关闭成功；回读可演示打开、已关闭、仍未知三种结果。
- 外部关闭演示复用本地行动收口，不仅仅更新标题状态。
- 终态迟到消息不重开 issue，也不启动下一轮。

离群/解散不是关闭 issue。本稿不提供虚假的真实离群或解散完成按钮；正式接入这些操作前须落实成员权限、访问撤销和在飞取消回执。此限制在群管理说明中保留。

## agent 卡片与整体状态

卡片绑定当前议题内该 agent 的行动。单个行动直接展示；多个行动优先展示未结束项并提供数量与展开入口。未承担行动的人显示旁观。在线状态独立显示，离线不等于行动失败或责任转移；离线行动不计作已完成。

| 行动阶段 | 展示与反馈 |
| --- | --- |
| pending | 等待接管；不冒充执行中 |
| accepted | 已接管、排队 |
| running | 执行中，展示该 action 的要求与最近更新时间 |
| blocked | 需要信息，提供补充资料入口；恢复原行动 |
| writing | 结果已生成，正在写入 issue；尚未完成 |
| completed | 结果已写入并确认，提供结果与追问 |
| unknown | 结果未确认；先回读，无法确定继续保留未知 |
| cancel_requested | 正在停止，尚未确认物理停止 |
| cancelled | 已收到停止确认 |
| failed/refused | 保留具体原因，不显示绿色完成 |

每轮汇总只统计本轮承担 action 的参与者，不用全群人数作分母。所有行动结束时显示“等待发起者查看、追问或关闭”，不自动关闭 issue。Vikunja 模拟记录可以查看已写入的结果评论。

动画只表达活动与状态转换：执行、写回、停止中使用不定量活动条；卡片变化用短暂淡入位移。活动条不是完成百分比，不模拟模型思考内容。无行动、阻塞、离线和终态不持续闪动。支持 prefers-reduced-motion；状态文字不依赖动画或颜色。

## 演示控制

右侧状态区底部提供手动模拟：

- 下一阶段：pending → accepted → running → writing → completed。
- 模拟阻塞：展示补充信息入口。
- 模拟写回未知：保留 unknown；回读行动结果可找到原评论或继续未知，不重新执行。
- 模拟外部关闭、模拟停止确认：观察 issue 关闭与物理停止的区别。
- 模拟关闭写入失败：关闭不伪报成功，回读决定当前状态。

“回读”会显示读取中，并保留失败/未知结果。不能通过移除警告冒充回读完成。模拟连接设置只显示保存提示，不声称已通过 TLS 或连接真实服务。

## 实现验收与交付边界

首个可用版本须从实际产品浏览器入口完成上述最小路径，并验证以下反例：

- 新群没有消息时直接进入可操作空态，不留在加载中；刷新后能列出并打开已有议题。
- 同时打开两个群及两个身份，延迟旧请求；新上下文不显示旧历史、不复用旧身份写入。
- 写入已可能成功但回执丢失，随后刷新消息或 action 列表；原未知和提交标识仍保留，查询不新增写入。
- 同一 agent 有两个未结束 action；完成其中一个，另一项仍在卡片和汇总可见。
- 输入草稿时收到无业务变化的心跳和真实状态变化；草稿、光标、焦点及滚动位置保留。
- 多参与者各自完成后不自动互答；关闭原 issue、停止确认和重开分别符合真源，重开不重跑。
- 真实权限拒绝、真实 Vikunja 写入失败、历史缺口都有局部原因和恢复入口；桌面和窄屏键盘可完成主路径。

这些用例检验现有功能，不新增逐步骤 review、截图审批或固定点击次数门禁。复用输入未变的有效证据。

### 既有原型验证

本轮已在 Ego 浏览器操作验证：

- 带显式对象创建 action，replyRequired=false 仍等待接管；正文与行动要求分开。
- 跨群切换后草稿保留；输入区在 1920×939 窗口内可见。
- 关闭包含在飞与排队行动的 issue：在飞显示停止中，输入被禁用；停止确认后显示已停止；重开不复活旧行动。
- 发现页跨 Relay 选择显示范围限制；建群、邀请接受、创建新议题可连续完成。
- 390×844 窗口无水平溢出，输入区固定可见；窄屏保留群/议题和发现入口。
- 1440×900 窗口输入区底部位于 899px；消息历史和右侧卡片各自滚动，不再撑高整页。
- 用同一对 peer/master 发起向上请求并带原因拒绝，issue 保持打开。
- 关闭写入失败后保留警告并禁用新行动；回读仍未知时警告不消失；回读确认打开后恢复。
- 行动结果回读找到原评论后完成，不重新执行；accepted、running、writing、completed 逐阶段更新汇总与卡片。
- 阻塞后补充资料恢复原行动；完成后追问创建第二轮，第一轮结果保留。
- 切回群恢复最近议题；浏览器 reduced-motion 仿真时不定量活动条动画为 none。

原型采用原生 dialog 承担焦点限制、Escape 关闭和焦点恢复；输入都有标签，动态反馈使用 aria-live。原型内状态存在内存，刷新会重置；浏览器后退历史与真实多设备同步不是本轮验收项。

机械视觉检查降级为正则：缺 htmlparser2/css-select/css-tree/domutils，未自动评估计算样式与对比度。其活动条警告按用途保留：这是运行中的不定量指示，不滚动文字或自动移动内容。字体密度沿工具界面保留。该检查不替代浏览器行为验证。

真实 Relay/daemon API、Vikunja 写入与身份、权限、持久补投、模型注入、终态回执、系统读屏器和手机软键盘仍未验证。设计原型可用于下一轮产品确认，不得作为这些运行能力的证据。
