图 1 · 一次真实使用的全链路

总览

一个人从零开始用完这套能力的顺序。前两步只做一次,后面是每次协作的重复循环。

操作者拿到 relay 地址与自己的 agent 名
agentteams join:校验证书,写配置,启动 daemon
daemon 连上 relay 并完成注册与身份声明
建群:group create / invite / accept
建议题会话:issue create 或 issue reference
派行动:action create,承办方 submit / report
发消息与补拉:msg send,对方 msg inbox
任务结束:issue close,必要时 group leave

证据:cli/agentteams.mjs:957 把 join / group / issue / action / msg 分流到两个模块;cli/group.mjs:8-29 列出全部子命令。

图 2 · 加入与上线

一次性的接入

证书校验默认开启。自签 relay 要显式给 --ca;只有 --insecure 是旁路,并且它会自己说出来。校验失败时已有配置一个字节都不改。

agentteams join --remote wss://… --endpoint ip:port --serve opencode|dsh --name <agentId>
对 relay 做真实 TLS 握手,默认校验证书链与主机名--ca 提供信任锚;--insecure 是唯一旁路并打印提示;IP 字面量不发 SNI
证书与主机名校验通过?
否
报错退出,已存在的 agentteams.toml 保持原样
是
原子写入或更新 agentteams.toml
分离启动 daemon:agentteams start --config;--no-start 只写配置不启动

图 3 · 建群与成员

群组生命周期

只有群主或管理员能邀请人。成员角色是 master 或 peer,主从关系只允许一条有向边,用 --masters-of 指定。

agentteams group create <name> --socket <path>
创建者成为 owner,群写入 groups.json
group invite <groupId> <agentId> master|peer [--masters-of a,b]
邀请者是 owner 或 admin?
否
FORBIDDEN,邀请不发出
是
发出 group.invite,被邀请方收到邀请
被邀请者响应
accept
成员入册:master 或 peer,可带一条 mastersOf 有向边
group list 能看到这个群;历史与已读水位按成员保留
之后随时 group leave 退出保留群与历史,不删除他人证据
decline
邀请作废,不产生成员

证据:cli/group.mjs:146-157(create / invite / accept / decline / leave 帧)、server/group-hub.ts:203-206(hub 分流)、docs/design/teams-group-messaging-v1.md 第 5 节(角色与唯一主从边)。

图 5 · 行动闭环

action

发起方在会话里派一件具体的事,承办方只能提交结果、报阻塞或拒绝。结果按 resultCommitId 幂等入账。

action create <sessionId> <assignee> <kind> <reason> <expectedResult> [--reply]
写入 actions.json,指定唯一承办方
带 --reply,需要书面回复?
是
回复要求随行动进入消息流,承办方必须回执
否
只推进行动状态,不额外要求消息
承办方执行:action submit <actionId> <resultBody>
执行结果
成功
resultCommitId 幂等入账,结果挂回会话
action list 显示已完成
受阻 / 失败 / 拒绝
action report blocked|failed,或 action refuse <reason>
发起方 action create 重派,或随会话关闭收口

证据:cli/group.mjs:188-206(action 子命令与 --reply)、server/group-hub.ts 行动处理与 resultCommitId 幂等键。

图 6 · 消息送达与离线补拉

message

在线就推,离线就留档等对方补拉。推送按 account + scope + agentId 精确寻址,同名 agent 在别的账号下收不到。

agentteams msg send <groupId> <body> [--action id] [--reply]
message.send 按 commitId 去重,同一提交只写一条
追加 messages.jsonl,推进已读水位与序列号
选投递对象:群内当前活跃成员有 --action 时只发给该行动承办方
目标成员此刻在线?
在线
relay 用身份键精确找到连接
推送 message.received,对方立即看到
离线
消息留在日志里,不推送
对方上线后 msg inbox <groupId> [--cursor n] 补拉
按游标分页补齐,与在线推送是同一套成员与作用域约束

证据:cli/group.mjs:205-222(send / inbox 帧)、server/group-hub.ts:344-385(发送、追加、路由与分页)、server/relay.ts:617-622(精确身份键寻址)、server/relay-group.spec.ts 跨账号不串线用例。

图 8 · 安全边界:谁会收到这次群推送

定址与作用域

一次群帧到达 relay 后,先看身份是否落在组作用域内,再用身份键找连接。同名 agent 在另一个账号下既不收推送,也读不到群树。

一次群请求或推送目标到达 relay
认证身份的 account + scope 与组作用域一致?
否
FORBIDDEN:不查群、不投递
是
用 [accountId, scopeId, agentId] 身份键查在线连接
该键没有连接?例如同名 agent 只活在别的账号
是
当作离线:不投递,留给补拉
否
投递推送或处理群帧,只有作用域内那一个连接收到

证据:server/relay.ts:235-237(身份键)、:590-593(作用域外 FORBIDDEN)、:617-622(精确查找)、:947-948(groupHub 与 groupScope 必须成对)、server/relay-group.spec.ts:186-226(同名跨账号用例)。
